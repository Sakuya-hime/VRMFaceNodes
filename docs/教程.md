# 从导入 VRM 到手机实时面捕

版本 1.3.0；操作环境 Windows / UE 5.8.2。本文采用**手机 Live Link Face → Live Link Hub → UE → VRMFaceNodes** 的实时流程。摄像头视频源是另一条流程，不要把手机面部源与 MetaHuman（视频）选项混用。

## 1. 准备手机与电脑

手机安装 Epic 的 **Live Link Face**，与电脑连接同一局域网。电脑需要启用 Live Link 和 MetaHuman Live Link 相关插件。自动发现还要求手机与电脑处于同一子网；VPN 或网络隔离可能阻止连接。

截至 2026-09-09，Epic 的[采集设备要求](https://dev.epicgames.com/documentation/metahuman/metahuman-animator-capture-device-requirements)列出：

- 本教程的 iOS MetaHuman 实时流程：**iPhone 12 或更新机型**。
- Android：**Android 13 或更高版本**；支持 Snapdragon **8 Gen 1、8+ Gen 1、8 Gen 2、8 Gen 3、8 Elite、8 Elite Gen 5**，以及 Google **Tensor G3、G4、G5**。
- **Snapdragon 8s 系列不支持**。芯片名称不能直接等同于某手机已获兼容验证，仍需核对官方机型要求。

旧 iPhone 的 ARKit 流程与此处 MetaHuman 实时流程不同；不要套用同一支持列表。

## 2. 导入模型

用 VRM4U 将 `.vrm` 导入内容浏览器。需要保留面部形态键时，**No MorphTarget 不勾选**；需要 IK 辅助骨骼时，勾选 **Generate IK Bone**。先在骨骼网格编辑器里确认闭眼和张嘴形态键能改变模型。模型本身缺少某个形态键时，本插件不会凭空生成该表情。

## 3. 连接手机 Live Link Face

1. 在手机上打开 Live Link Face，保持人脸可见。iOS 的 Capture Mode 选 **MetaHuman Animator**。
2. 在 Live Link Hub 的添加来源菜单中选择实时 **Live Link Face / Live Link 面部源**。不要选 **MetaHuman（视频）**，也不要把用于采集管理/离线导入的 **Live Link Face Device** 当成实时来源。
3. 选择手机设备、填写主题名，点击 Connect。设备未自动发现时，手工填入手机的局域网 IP；默认端口为 **14785**。
4. 在 Hub 客户端中确认 UE 已连接。进入 UE 的 Live Link 面板，核对主题出现，并且张嘴/眨眼时曲线持续更新。客户端显示 Connected 只能证明连接，不能证明手机仍在发送新数据。

Hub 回放录制时也要使用相同主题名。本插件不要求先创建一个完整的 MetaHuman 角色，使用的是该流程提供的面部曲线。

官方：[使用 Live Link Face 来源](https://dev.epicgames.com/documentation/metahuman/using-a-live-link-face-source?lang=en-US)。

## 4. 接入面捕

停止运行，打开 **工具 → 面捕设置**，选择导入的骨骼模型，填入 Hub 的相同主题名，指定输出文件夹，点击 **接入面捕并放入场景**。默认示例主题应替换成自己的名称。

插件生成新的模型、骨架和动画蓝图副本，原模型保留。主动画蓝图的接法为：

```text
参考姿势 / 原有身体动画 → 面捕 · 自动面部捕捉 → 输出姿势
```

自动节点与分步节点选一种接法，避免同一帧重复增强。身体动画可放在自动节点前；各模块的用途见[功能说明](功能与限制.md)。

## 5. 运行、校准、微调

运行场景，再从 **工具 → 面捕设置** 打开独立配置窗口。没有游戏画面内的浮层，也没有专用快捷键。

- **面部增强** 默认开启，关闭即切回基础映射。
- 点 **重新校准 · 五步**，按提示做自然表情、闭眼、普通张嘴、最大张嘴、抬眉。约 35 秒，换动作有提示音，完成自动保存。不要求左右幅度完全相同，未测到可靠变化的步骤保留原范围。
- 摄像头偏放时，坐正看屏幕，点 **校正摄像头**，保持约一秒。这只校正朝向与视线零点，不能恢复摄像头看不到的细节。
- 展开 **面部微调**，调整说话幅度、前置镜像等，修改即时使用并自动保存。默认说话张嘴倍率 1.15；更多形态键倍率为可选项。
- **恢复原下巴** 只把额外补偿归零，原张嘴形态键继续工作。开源包没有作者专用几何配置，普通模型不会自动获得这项附加变形。

配置管理位于折叠区，支持新建、复制、改名、删除及 JSON 交换。存档在项目 `Saved/SaveGames`，JSON 在 `Saved/VRMFaceNodes/Profiles`。换模型应重新检查形态键倍率；换面捕者建议重做五步校准。

## 6. 可选：修复腿脚 IK 链

这是本机 **VRM4U 导入 VRoid Studio 模型**时复现的链配置问题，并非声称所有设备或 VRM4U 版本均有问题。**不使用 IK 重定向来驱动角色行动时，可跳过。**

| 受影响链 | 本机错误结果 | 修复与影响 |
|---|---|---|
| LeftLeg / RightLeg（2 条） | UE 源腿链终点为 `ball_l / ball_r`（脚趾） | 改为 `foot_l / foot_r`（脚踝），避免目标脚跟被放到源脚趾位置而前移 |
| LeftToe / RightToe（2 条） | 脚趾目标链误映射到 `LeftArm / RightArm` | 只映射同侧 ball 骨骼的单骨源链，避免脚尖朝手臂方向扭转；不存在合适链时设为 None |

两类链 × 左右两侧，共四条。在停止运行时打开 **面捕设置 → 腿脚修复**，选择 VRM4U 的 IK 重定向器，先检查，再修复。仅支持代码检查通过的标准 **UE → VRoid** 骨架与层级；自定义骨架不会猜测处理。

修复生成专用源 IK Rig 和 RTG 副本。后续重定向要改用生成的新 RTG。不会移动参考模型、修改模型骨骼参考姿势或形态键，也不会改动共用源 IK 资产；回退时选回原 RTG。已正确的四条链不重复修复。

## 排查

| 现象 | 先检查 |
|---|---|
| 模型不动 | 手机正在发送、Hub 权重更新、UE 客户端和主题名一致 |
| 没有张嘴/闭眼 | 导入保留了 morph，模型有对应形态键，动画蓝图接入副本 |
| 嘴巴轻动就张满 | 重做普通张嘴和最大张嘴步骤，避免把普通幅度当上限 |
| 左右方向怪 | 使用前置镜像总开关，避免再叠加另一层左右反转 |
| 牙齿仍穿模 | 开源包不含作者模型专用修正几何；需模型自身提供兼容修正形态键 |
| 配置窗口无运行项 | 先运行已接入自动面捕节点的场景，再从工具菜单打开 |

首次使用建议在项目副本中验证；插件自动生成的资产与个人配置可以独立回退。
