# 功能、节点与适用边界

## 映射基础

`Content/Presets/BP_ManualFacialRemap` 是木花开耶姬手调映射的独立副本，保留 `RemapCurveElements`、`GetRemappedCurveName` 及内部宏。MetaHuman 输入经过此预设，再统一为语义通道。直接提供 ARKit 通道时优先使用这些通道。缺少有效输入或未识别的模型形态键不会被当成万能自动修复。

## 模块职责

| 模块 | 作用与原理 |
|---|---|
| 自动面捕 AnimNode | 读取 Live Link、规范化通道、应用映射与增强，再输出形态键和头眼骨骼 |
| Manual Mapper | 调用作者手调蓝图，将左右方向统一后交给总镜像；限制闭嘴补偿不超过可用张嘴量 |
| Calibration / Guide | 记录自然起点、普通与最大张嘴等输入范围；分段响应避免说话时很快饱和 |
| Stability | 根据输入变化和运动状态抑制短时权重回落，同时限制表情延迟 |
| Head / Eyes / Body | 统一镜像、头眼基准校正、八向视线和上身跟随；姿态骨架不同需验证轴向 |
| Profile Manager | 独立存档、倍率微调、自动保存与 JSON 配置交换 |
| IK Repair（编辑器） | 检查标准源/目标链，复制后修正四条链并复查；不改模型参考姿势 |

更细的拆分节点用于自定义蓝图；日常使用自动面捕节点即可。

## 牙齿与下巴的区别

运行时可输出 `VRoid_TeethRetract`、`VRoid_MouthInnerRetract` 和 `VFN_ChinAssist` 等修正权重，但模型必须已有方向与含义正确的修正形态键。只给曲线改名不会创造正确的几何变化。

演示模型使用的 `Resources/VerifiedMouthProfile.json` 包含顶点选择与位置验证，属于模型专用数据，已从公开版本排除。创建修正的编辑器功能会在缺少该文件或几何不匹配时退出，保留原模型。不开这个配置不会阻止面部映射、校准、镜像和腿脚 IK 修复。

因此演示中的额外牙齿后移、下巴补偿**不能承诺下载插件后对任意模型自动复现**。本版本不提供通用口腔拓扑识别。用户拥有合法模型并自行制作兼容形态键后，可使用对应的运行节点权重。

## VRM4U 与本插件

VRM4U 负责导入模型和生成基础资源。本插件独立工作，不覆盖其源码。作者本机曾额外修改 VRM4U 导入界面的中文标题、可选腿脚修复与导入选项缓存；这些不是本仓库对所有 VRM4U 安装自动施加的补丁。本仓库提供单独的导入后 IK 修复工具，未修改过 VRM4U 的用户也可按支持范围检查与修复。

面部增强关闭时，保留基础映射、方向与基础头眼驱动，关闭个人表情校准、防抖、牙齿避让和额外下巴补偿。它不等同于完全不使用本节点。教程右侧“VRM4U 直接导入”单独采用 VRM4U 生成的原始表情姿势，用于真实的三组对比。
